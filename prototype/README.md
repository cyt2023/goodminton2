# 单机落点原型 v0.1（2026-11-22）

一部 iPhone 录像 → 场地标定 → TrackNetV3 追踪球 → 找落点 → 映射到场地坐标 → 带误差范围判 界内 / 出界 / 无法判定 → 生成回看页。

单机只能定位**地面上**的点，所以落点靠"球从飞行中到达、随后静止在地上"来识别。双机三角测量是下一阶段。

## 运行环境

复用 `04_原型/.venv-vision`（OpenCV、NumPy、PyTorch、TrackNetV3 权重已在里面）。以下命令都在本目录下运行：

```bash
cd prototype   # 在仓库根目录下
```

```bash
PY=../../04_原型/.venv-vision/bin/python
```

## 用法

**1. 标定（每次机位变动都要重做）**

```bash
$PY calibrate_server.py 录像.mov --out ../runs/实验名 --time 2
```

浏览器打开 http://127.0.0.1:8770 。在左侧场地小图上选一个交点，再到画面里点它；滚轮缩放，拖动平移，右键删除。至少点 6 个，尽量分散，最好覆盖要判的那几条线附近。点"保存并拟合"后，检查粉色投影线是否和真实场地线重合。

- "近端"是 y=0 那一端，左右按"站在近端看向球网"来分。
- 静态精度实验可以切到"测量点"模式，点击放在地上的球的球托接地处。

**2. 自动找落点并判定**

```bash
$PY run.py analyze 录像.mov --run ../runs/实验名 --mode singles
```

第一次会跑 TrackNetV3（720p、36 秒的录像在 M4 上约 73 秒），结果缓存在 `trajectory.json`。输出：

- `index.html`：回看页，每个落点有放大图、慢放片段和数值。页面下方单独列出"不像回合落点"的候选（颠球、丢球、捡球），方便有争议时回看。
- `landings.json`：全部数值、设置，以及 `non_rally_candidates`（回合过滤排除的）和 `rejected_candidates`（不在地面或远离球场的）。

`--no-rally-filter` 关闭回合过滤；`--min-rest-s` 改落地后最短静止时间（默认 0.6 s）。
- `court_map.png`：俯视落点图。

**3. 静态测量点（E1 受控实验用）**

```bash
$PY run.py measure --run ../runs/实验名
```

输出每个测量点的场地坐标、σ、到边界的有符号距离（正数是界内）和判定，写入 `measurements.json`。

**4. 场测会话（人判 + 机器 + 真值）**

流程、手机摆放和首测要回答的六个问题见 [../场测指南_v1.md](../场测指南_v1.md)。

```bash
$PY session.py init ../runs/场测1 --system A.mov --reference B.mov --line right --ref-court-side left
```

```bash
$PY session.py prepare ../runs/场测1
```

```bash
$PY session.py annotate ../runs/场测1
```

```bash
$PY session.py report ../runs/场测1
```

- `prepare`：
  - 用声音对齐两部手机（`audio.py`，用 macOS 自带的 `afconvert` 抽音轨，不需要 ffmpeg）；
  - 找喊声；
  - 把机器落点（目标线 1 m 以内）和喊声合并成候选，写入 `candidates.json`；
  - 重跑不会丢掉手动添加的落点，也不会动已有标注。
- `annotate`：标注页面在 http://127.0.0.1:8771（`annotate_server.py`），帧由服务器用 OpenCV 解码，iPhone 的 HEVC 和 240 fps 都能逐帧看。在参照机画面上依次点线的两边、球托的两边，就能算出球托内沿到线外沿的距离：用线宽 40 mm 作比例尺，球托宽度读数用来检查。页面还用来标喊判、标误报、手动添加漏掉的落点、微调偏移。结果写入 `annotations.json`。
- `report`：`report.html` 和 `report.json` 回答六个可行性问题；近线喊判有 15 个以上时，拟合心理测量曲线（`psychometric.png`）。

- `test_session.py`：检查点击真值的几何、候选合并、声音对齐和心理测量拟合。

## 方法要点

| 环节 | 做法 |
|---|---|
| 场地 | BWF 尺寸；关键点取线中心交点；判定边界取边界线**外沿**，压线算界内。正式实验前用卷尺实测，需要时用 `--court-file` 覆盖 |
| 标定 | 单应矩阵在像素空间做最小二乘（点击噪声在像素里）；点击噪声取先验 1.5 px 与残差估计中较大的那个；对点击加噪重拟合，得到 400 个单应矩阵样本 |
| 落点 | 只用 TrackNet 实际检出的点，不用 InpaintNet 补出来的点；静止 ≥0.3 s，且此前 1.5 s 内球在远处，才算候选。检出点先连成"飞行链"（相邻检出 ≤0.15 s、速度 ≤2.5 倍画面宽/秒），孤立误检不会被当成飞行；接触帧取飞行链之后第一个到达静止点的检出帧，运动项速度取飞行链末端速度 |
| 回合过滤 | 候选要同时满足：①落地前 1.5 s 内有一段 ≥5 个检出、跨度 ≥0.08 倍画面宽的飞行链，且末端在间隙时间内够得着静止点（允许最后一段被人挡住）；②落地后在静止点停留 ≥0.6 s。不满足的（颠球的最高点、手里丢下、马上捡起）单独列出，不计入落点 |
| 接触像素 | TrackNet 给的是球心，比地面高几厘米，直接投影会把落点推远。所以取帧差斑块的最低点（球托）；取不到时退回球心，并把像素噪声放大到 6 px |
| 不确定性 | 蒙特卡洛：单应矩阵样本 × 像素噪声（检测噪声 2 px，加上一帧内运动的均匀分布项 v²/12）；P(界内) = 落在界内的样本比例 |
| 判定 | P ≥ 1−α 判界内，P ≤ α 判出界，其余无法判定（α 默认 0.05）。像素噪声碰到地面"地平线"时，一律无法判定 |
| 排除 | 静止点在画面地平线以上（球网、墙、背景），或距双打边界超过 3 m，不算落点，单独列出 |

## 冒烟测试结果（`../runs/d64275f3_smoke`）

用现有录像 `单打视频/629614…d64275f3.mp4`（1280×720，30 fps，相机低位放在底线后）跑通了全流程。**这不是精度评测：**标定点是从放大截图里目测读的，没有用标定工具点；也没有真值。

- 标定 9 点，都在近半场；重投影 RMS 2.9 px。投影线和真实场地线目测重合。
- 检出 4 个静止候选，逐帧看过录像：
  - 第 88 帧：远端扣杀，近端扑救没够到，球落在近端前发球线和网之间，**真落点**。保留，判界内（正确）。
  - 第 373 帧：回合之间，远端把球轻拨过来，近端没接，球落在脚边，0.6 s 内被拍子捞起。回合过滤因"静止太短"排除（正确）。不过 TrackNet 在捞起前就丢了球，实测静止 0.33 s；如果球在地上多停一会儿，这条规则就拦不住。
  - 第 196、319 帧：颠球的最高点等，在地平线以上，已排除，也不满足回合条件。
- 加回合过滤时修了两处落点本身的问题：①原来"到达"靠单个远处检出判断，第 88 帧前恰好有一个误检，算出的运动速度是 385 px/帧，误差范围爆炸，被错判成无法判定；现在用飞行链，速度是 21 px/帧。②原来接触帧取到达后第一个检出，球还在下落途中（第 371 帧比静止点高 35 px）；现在取第一个到达静止点的帧。
- 第 88 帧的场地坐标是 y = 7.0 m，落到了网的另一侧，实际约在 5–6.5 m。原因是目测标定只有近端的点，网附近外推偏差大（叠加线在这里明显对不上）。判定没错，但位置不可信。
- 地上原本就放着的一个球（测量点）判出界，距右双打边线约 0.69 m，与画面一致（球在两块场地之间）。
- 30 fps 时，一帧内运动项占误差的大头（界内那个落点 σ 约 9 × 29 cm）。这说明帧率对精度影响很大，是 RQ1 要测的因素。

## 已知限制 / 下一步

1. 回合过滤只看球的轨迹，分不出"回合之间把球打过来、对面不接"和真正的回合落点，只能靠落地后静止时间区分，这一点不可靠。更可靠的做法是加上击球检测（`04_原型` 的击球声或姿态），要求落点前有一串来回击球；或者实验时直接记录每个回合的起止时间。阈值（0.6 s、0.08 倍画面宽）只在 4 个候选和合成轨迹上看过，需要用 E2 的录像标定。
2. 接触帧只精确到整帧；240 fps 能把运动项缩小约 8 倍。还可以做亚帧插值。
3. 球托最低点的取法只在相机高于地面、球附近没有遮挡时可靠，需要在 E1 里实测偏差。
4. `--contact-radius`（球托接地面积）默认 0，需要实验确定。
5. 只判回合中的边界，不判发球区。
6. 双机：同步、三角测量、3D 轨迹求 z=0。

## iPhone 录像设置（E1 / E2）

- 用三脚架，锁定曝光和对焦（相机 App 里长按画面出现 AE/AF 锁定）；不要变焦，固定用 1× 主摄。
- 关闭视频防抖（设置 → 相机 → 录制视频 → 增强防抖关闭），因为防抖会改变画面几何。
- 帧率：4K 60 fps 或 1080p 240 fps 慢动作；4K 120 fps 需要 iPhone 16 Pro 及以上。先在场馆试拍，确认 LED 灯在该帧率下不闪。
- 机位尽量高（1.8–2.5 m），斜对着要判的线；整块场地，或者至少要判的线附近，都要清楚地在画面里。
- 每次开拍前后都拍几秒空场，用来标定，并检查场地或机位有没有移动。
