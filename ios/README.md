# 手机鹰眼 iPhone Demo v0.1（2026-11-22）

一部 iPhone 横屏架在三脚架上录普通视频（1080p 60 fps），App 在手机上完成全部处理：标定场地 → TrackNetV3（Core ML）找球 → 找落点 → 判界内 / 出界 / 判不了（带误差范围）→ 慢放回看。全部离线，不联网。

## 安装到 iPhone（第一次约 30 分钟，大部分时间在下载 Xcode）

1. **装 Xcode**：Mac 上打开 App Store 搜 Xcode，免费，需要 10 GB 以上空间。装好后打开一次，按提示装 iOS 平台组件。
2. 双击打开 `06_鹰眼课题/ios/HawkEye.xcodeproj`。
3. **签名**：左侧点项目 HawkEye → Signing & Capabilities：
   - Team 选你的 Apple ID（没有就点 Add Account 登录，免费账号会显示 "Personal Team"）；
   - 如果提示 Bundle Identifier 被占用，把 `org.badmintonresearch.hawkeye.k7q2` 末尾改成别的字母。
4. **手机准备**：用数据线连上 Mac，手机上点"信任"。打开 设置 › 隐私与安全性 › 开发者模式，然后重启手机。
5. Xcode 顶部的设备选你的 iPhone，点 ▶ 运行。
6. 第一次运行时，手机可能提示"不受信任的开发者"：设置 › 通用 › VPN 与设备管理 › 信任你的 Apple ID。

免费账号装的 App 7 天后会失效，到时连上电脑再点一次 ▶ 就行。

## 实时比赛（首页第一个按钮）

1. **摆手机**：横放在三脚架上，斜对着要判的线，整块场地尽量都在画面里。点画面对焦，然后打开"锁定曝光/对焦"。光线够的话再打开"快门 1/1000"。
2. **标定场地**：点"标定场地"，App 会截下当前画面，在上面点场地线交点（先点几个角，再点要判的线附近的交点，至少 4 个，6 个以上更好），再选单打或双打，点"用这个标定"。黄色边界会叠加在相机画面上，用来检查标定对不对。
3. **开始比赛**：之后不要再碰手机。前 4 秒在建立背景，这段时间里的球也会被处理，不会丢。比赛中：
   - 画面上的橙色点是当前找到的球；
   - 每次球落地约 1 秒后，右上角显示判定（界内 / 出界 / 判不了），并振动一下。
4. **回放**：点右上角"回放"，看上一个落点：
   - 左边是触地那一帧的截图，叠有边界、落点和 95% 误差椭圆；
   - 右边是 3D 场地：可以拖动旋转，"近看"是从线外贴地看过去，"全场"是俯视；
   - 用左右箭头切换前面的落点。
   - **3D 里的飞行轨迹只是示意**：单机测不了高度，只有落点和误差椭圆是测量值。
5. **结束比赛**：录像和全部落点保存成一条记录，可以在回看页逐个慢放，也可以导出到电脑。

实时处理的要点：
- 每帧缩成 512×288 交给 TrackNet，8 帧一批；
- 落点检测每批之后在最近 8 秒的轨迹上重跑一次，落点确认后只报一次；
- 如果处理跟不上，会跳过帧，画面上会提示，可以改用 30 fps。

在 Mac 上，用录好的视频逐帧模拟实时（`tools/cli-live`）：落点在触地后 1.04 s 确认，结果和离线分析一致。

### 标定：先自动识别，不对再点四个角

- **自动识别**：打开标定页会先自动识别场地线。只有大部分场地都在画面里、而且落在识别出的线上，才会采用自动结果，否则直接进入"点四个角"。自动结果一定要对照粉色线检查。
- **点四个角**：按右边小图提示的顺序，点双打场地的四个外角，顺序是近端左、近端右、远端右、远端左（左右按站在手机这一端看过去）。App 会补全其余交点；如果能对齐到画面里的线上，还会自动吸附过去。
- **逐个修改**：个别点不准，可以展开"逐个修改交点"单独改。
- **自动识别目前不可靠**：在现有的测试录像上，它多次对到旁边场地的线，或者干脆认不出来。原因是这些录像多是侧面机位、多块场地并排，或者用了 0.5× 广角镜头。要按真实摆法（底线后居中、1× 镜头）的录像来调，所以现在主要靠"点四个角"。

### 双机模式

1. **安装**：两部手机都要装 App，每部手机连电脑点一次 ▶。
2. **摆放**：每部手机放在一端底线后面的中间，三脚架尽量高，整块场地都在画面里。
3. **选角色**：都打开"实时比赛"，左上菜单一部选"双机 A 端（主机）"，另一部选"双机 B 端"。两部手机会通过 Wi-Fi/蓝牙直接连上，不需要路由器，第一次会问能否访问本地网络，选允许。连上后 B 端会自动对齐两部手机的时钟。
4. **标定**：两部手机各自标定。每部手机都以自己这一端为"近端"，不用管另一部手机。
5. **开始比赛**：在 A 端点"开始比赛"，B 端会自动一起开始。
6. **判定怎么合并**：
   - B 端的落点会旋转 180° 换算到 A 端的场地坐标，连同截图发给 A 端。
   - A 端把 0.35 s 内、1.5 m 以内的两个落点认作同一个，按误差大小加权合并（离得近、看得清的那部手机权重大），再重新算 P(界内) 和判定。
   - 只被一部手机看到的落点，就用那部手机的结果。B 端结果晚到时，会更新已经显示的那个落点。
7. **回放**：A 端点回放，可以看到两端各自的截图和各自的判定，大字是合并后的判定。

已验证：在两台模拟器上用同一段录像（关掉旋转）测过配对、时钟对齐、自动同时开始、落点合并和回放；合并后误差从 ±523 mm 降到 ±341 mm。还没在两部真手机、真场地上试过。

## 录像后分析（怎么用）

1. **录**：点"录一段新视频"。
   - 手机横放（Home 条在右边），三脚架尽量高（1.8–2.5 m），斜对着要判的线，整条线都在画面里。
   - 点画面对准要判的线附近，再打开"锁定曝光/对焦"。
   - 光线够的话打开"快门 1/1000"，可以减少球的拖影；状态栏如果提示 ISO 到上限，说明光线不够，关掉这个选项。
   - 防抖已自动关闭。
2. **标定**：在右边列表选一个场地线交点，再到画面里点它（两指放大，越准越好）。
   - 至少 4 个点，最好 6 个以上，分散在要判的线附近。
   - 点"检查"，看粉色线和场地线是否重合，重合就保存。误差大于 5 px 多半是点错了交点。
   - 选好单打还是双打。
3. **分析**：点"开始分析"，App 保持在前台。
4. **回看**：
   - 列表显示每个落点的判定、P(界内)、离线距离 ± 误差；
   - 点进去可以 1/4 速循环慢放，画面上叠有黄色判定边界和彩色 95% 误差椭圆，"定格触地帧"可以停在触地那一帧；
   - "记录（研究用）"里可以记球员当场的判定，以及这是不是误报。
5. **把数据拿回电脑**：文件 App › 我的 iPhone › 手机鹰眼 › Sessions，每次录像一个文件夹（`video.mov` + `session.json`），可以 AirDrop 到 Mac。

**导入**：也可以从相册或文件导入别的手机拍的视频（必须横屏）。

## 怎么判的（和 Mac 原型 `prototype/` 是同一套方法）

| 环节 | 做法 |
|---|---|
| 找球 | TrackNetV3 转成 Core ML（`tools/convert_tracknet.py`）。在 392 帧真实画面上和 PyTorch 对照：227 次检出全部一致，位置差 ≤ 0.5 px |
| 落点 | 球从飞行中到达、随后停在地上；回合过滤要求落地前有连续飞行、落地后停够 0.6 s |
| 标定 | 场地线交点拟合单应矩阵，先线性求解，再在像素空间做 LM 优化；对点击加噪重拟合 200 次，表示标定误差 |
| 误差和判定 | 蒙特卡洛：标定样本 × 像素噪声（6 px，加上一帧内运动项）。P(界内) ≥ 0.95 判界内，≤ 0.05 判出界，其余判不了；离地平线太近也判不了。压线算界内（考虑了 13 mm 的球托半径） |

## 已知限制

- **单机只能定位地面上的点**，靠"球停在地上"认出落点；离相机远的落点误差大，经常判不了。
- **落点像素用的是 TrackNet 给出的球心**，没有像 Mac 原型那样取球托最低点，所以像素噪声设成了 6 px。这是下一步要补的。
- **分析是录完以后做的**，不是实时判。
- **已验证 / 未验证**（2026-11-23，Xcode 27.2）：
  - 模拟器版和真机版都编译通过。
  - 模拟器（iPhone 17）里跑通了分析、回看列表、落点慢放和标定页：结果和 Mac 一致，在 567 帧里找到球，第 88 帧落点判不了，P = 0.785。
  - **模拟器跑不了这个半精度（FP16）模型**：它的 Core ML 对这个模型只输出 0，所以分析结果是"0 帧找到球"。测试时我临时换成 FP32 模型才跑通。真机用神经网络引擎跑 FP16，Mac 上的神经引擎/GPU 和纯 CPU 两条路径也都正常，所以 App 里放的仍是 FP16 模型。
  - 还没验证：真机上的录像界面和分析速度；在模拟器里点击标定（需要你授权模拟器面板）。
  - 实时比赛（2026-11-23）：在模拟器里用调试用的视频源代替相机，跑通了"标定 → 开始比赛 → 落点判定 → 截图 → 回放 3D"。
    - 已装到 iPhone 16 上；
    - 还没在真机上用相机实测，所以真机能否跟上 60 fps 的实时处理还不知道。

## 开发者备注

- **Mac 上测试核心代码**（不需要 Xcode）：

  ```bash
  cd ios   # 在仓库根目录下
  ```

  ```bash
  swiftc -O -o /tmp/hawkeye-cli HawkEye/Core/*.swift tools/cli/main.swift
  ```

  ```bash
  /tmp/hawkeye-cli 视频.mp4 ../runs/某次/calibration.json HawkEye/Resources/TrackNetV3.mlpackage singles
  ```

  在 M4 上处理 720p 视频约 260 帧/秒。
- **重新转换模型**：

  ```bash
  ../.venv-coreml/bin/python tools/convert_tracknet.py 视频.mp4
  ```

- **代码结构**：
  - `HawkEye/Core`：平台无关的算法，iPhone 和 Mac 共用；
  - `HawkEye/App`：iPhone 界面；
  - 工程用 Xcode 16 的文件夹同步，往 `HawkEye/` 里加文件会自动编进 App。
